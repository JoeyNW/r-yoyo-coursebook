# 悠悠课程本｜Cursor 项目交接文档（V1.0）

> 文档日期：2026-10-08  
> 方案版本：**V1.1（同日复审，取代下文中与之冲突的技术句子）**  
> 项目性质：家庭自用的儿童课程课时管理工具  
> 目标：交给 Cursor Agent 作为需求、技术选型与实施的单一初始上下文。  
> 当前阶段：**尚未开始开发。先做本地 H5。PWA 与微信小程序都不是 V1。**

## 复审结论（V1.1，实现以此为准）

产品目标不变：全家看同一本账，打卡扣课准确，历史可追溯。复审只收紧会在实现时分叉的决定。细节与表结构见 `docs/DECISIONS.md`。

1. **前端定为 Vue 3 + Vite + TypeScript。** 小程序未承诺、也不在本阶段验证。uni-app 的条件编译会拖慢 H5，而 API 已与页面分开，以后真做小程序再重写界面。
2. **未来课不落库。** 日历上的「计划」由每周时段按日期推算。只有打卡、请假、取消、补课、撤销才写入 `lesson_records`。避免预生成行被改课表时改写。
3. **首页「已上课」只打今天尚未记录的那一节。** 今天多节就进入当日列表；今天没有课不扣任何一天。补录走日历。
4. **每门课有一个当前课包。** 快捷打卡只扣当前课包。余量为 0 时拒绝并提示更换，不自动挪用另一期。
5. **建课包时可填「启用前已用课时」。** 这是一条调整记录，不用伪造多条历史打卡。
6. **`member` 可以打卡和纠错，不能改课程、课包、排课和成员。** 这些只属于 `owner`。
7. **生产部署默认 systemd + venv + Caddy，不用 Docker。** 1 GB 内存上还跑着 VPN。本地开发用 uvicorn 与 Vite，不强制 Docker。
8. **登录用 HttpOnly Cookie，页面和 API 同域。** 适配微信内置浏览器。V1 不做 WebSocket，另一台手机刷新后看到结果即可。

## 0. 给 Cursor 的执行指令（请先阅读）

你是本项目的全栈开发助手。请以本文档为产品和工程约束，先检查本地开发环境，再给出简短实施计划，并按可运行、可测试、可部署的顺序逐步实现。**不要只生成漂亮的静态页面**，核心必须是真实的多人共享、数据持久化、课时准确核算。

工作原则：

1. **MVP 优先**：只做必要功能；不接入 AI 大模型、支付、复杂管理后台或商业化能力。
2. **云端数据唯一事实来源**：不可使用浏览器 `localStorage` 作为课时记录的唯一存储。
3. **课时扣减必须准确**：同一节课不能重复签到扣课，编辑或撤销有明确规则；并发请求不能导致重复扣减。
4. **家庭共享要安全**：家庭成员经授权后共享课程，其他人无法浏览或修改。
5. **小 VPS 优先**：部署目标为 AlmaLinux 9、1 GB RAM，已有 VPN 正在运行；不得擅自重装系统、调整 VPN、改变已有防火墙规则或抢占生产端口。
6. **保留未来小程序迁移能力**：采用清晰的前后端 API 边界，后端和数据库模型不依赖 H5 页面框架。
7. 若细节未明确，先采用本文“默认规则”；真正影响课时扣减或生产 VPN 安全的关键决策再向用户确认。

建议先交付：项目目录、README、本地运行命令、示例初始数据、测试以及部署文档，再做 VPS 上线。任何实际线上操作需用户明确授权。

## 1. 背景与目标

悠悠目前参加**英语课、舞蹈课**，家人经常记不清已经上了多少次，担心多扣、少扣、剩余课时不清楚。希望全家可以在手机上快速打卡，实时查看同一份记录。未来可继续添加新的课程或新一期课包。

示例课程安排：

- **英语课**：每周一 **16:30**、每周五 **19:00**。
- **舞蹈课**：有课程，但具体上课时间、课包总数尚未给出；在应用内可自行设置。
- 上述英语排课为已知需求；**示例界面中出现的 24/12/18 等课时数字不是实际报名数量**，不能写死成真实数据。

核心成功标准：

- 任一家人打开手机，能够在几秒内查看每门课程的**总课时、已消耗、剩余**。
- 上完一节课，点击一次完成打卡；所有已登录、已授权家人立即或刷新后可以看到结果。
- 日历能区分计划课程、已完成、请假、取消和补课。
- 允许补录过去某天记录、纠正误操作，但不能悄悄破坏账目。
- 新增课程、续报下一期课包时，历史数据仍完整保留。

产品暂定名：**悠悠课程本**（可修改）。语言：**简体中文**；时区：**Asia/Shanghai**，日期格式 `YYYY-MM-DD`，显示 24 小时制。

## 2. 已确定的产品与技术路线

### 2.1 第一阶段：H5 网页

- 首先交付**手机优先的响应式 H5**，可在 iOS、Android 浏览器以及微信内置浏览器使用。
- 之后可加入 **PWA**（添加到主屏幕），但**可靠的系统推送提醒不属于 V1 必需项**。
- **不做 iOS/Android 独立原生 App**。
- 家庭共享必须依赖服务器 API + 数据库；**不购买腾讯云作为必要前提**。

### 2.2 未来：可迁移微信小程序

- H5 先用起来，之后根据真实使用习惯决定是否开发微信小程序。
- **后端 API、业务逻辑、历史数据应该复用**；前端 UI 可能需要适配或重写；微信登录逻辑另行对接。
- **V1.1 已选定 Vue 3 + Vite + TypeScript。** 不再并行评估 uni-app。后端 API 与数据库不依赖该框架，以后若做小程序，重写前端即可。
- 微信小程序上线未来涉及账号注册、个人主体资料、小程序备案、代码审核、隐私合规、合法请求域名和可能的 ICP 备案要求。**届时以微信和主管部门最新规则为准**，不要假设日本 VPS 上未备案的 API 域名必然满足发布要求。

### 2.3 AI 工具

- **Cursor Agent 是主要开发工具**。
- ChatGPT 可辅助需求评审、架构、代码复核和验收。
- 对比过 WorkBuddy、Grok Bot，但本项目不需要让多个 Agent 同时接管同一个仓库。

### 2.4 推荐后端与存储

- **Python FastAPI**：用户熟悉 Python，开发维护方便。
- **SQLite**：家庭自用、低并发，先不引入单独运行的 MySQL/PostgreSQL 服务。
- **Caddy**：静态文件、HTTPS、把 `/api` 反代到本机 FastAPI。页面与 API 同域。
- **生产不用 Docker。** 用 systemd + Python venv + 单进程 uvicorn。Docker 在 1 GB 内存上还要让给 VPN 和 SELinux，不划算。
- **不在生产 VPS 上运行前端开发服务器或 Node.js。** 前端在本地构建为静态文件再上传。
- 本地开发：后端 uvicorn，前端 Vite 代理 `/api`。Windows 本机可直接跑，不要求 WSL。

## 3. 第一版功能范围（必须实现）

### 3.1 课程管理

每门课程支持：

- 课程名（如英语、舞蹈；支持任意新增）；
- 可选颜色/图标；
- 可选上课机构、老师、备注（不应阻碍快速创建）；
- 每周重复上课时段，可以有**多个**时段（例如周一 16:30 + 周五 19:00）；
- 启用/停用状态；停用后保留历史数据。

### 3.2 课包/期数管理（与课程分开）

每次报名或续费是一份独立课包，应保存：

- 关联课程、期次/名称；
- 购买总课时（正整数），以及可选的「启用前已用」；
- 可选开始日期、到期日期、费用、备注；费用只保存，V1 不做统计页；
- 已用和剩余只按 D5 公式计算，不另存一份余额；
- 历史课包可查看，续报新课包**不能覆盖旧课包数据**。

默认按**每次已上课消耗 1 课时**，但数据结构最好保留 `consumed_units`，便于将来支持一堂课扣 2 课时、赠送课时、机构特殊规则。第一版界面暂不需要复杂配置。

### 3.3 上课记录 / 一键打卡

- 首页「已上课」只作用于**今天**、该课程尚未记录的最早一节。今天有多节时进入当日列表再选。今天没有待打卡课程时不扣课时。
- 补录、请假、取消、临时补课在日历里对指定日期操作。
- 日历上的计划课由排课规则现算，状态名为 `scheduled`，**不写数据库，不扣课时**。
- 落库状态：`attended`（已上）、`leave`（请假）、`canceled`（取消）。临时补课是手工新增的 `attended`，用来源 `manual` 区分，不单独做一种会和出勤打架的状态。
- 默认只有 `attended` 扣 1 课时。请假、取消不扣；请假要扣时必须勾选「扣课时」。
- 同一节重复点击返回原记录，不扣第二次。两人同时打卡也只成功一条。
- 撤销保留原记录并标记作废，余额恢复，操作日志留下快照。作废后可以再打同一节。
- 课表里没有的补课可以手工新增，同一天允许多节补课。

### 3.4 家庭共享

- 至少支持 2–4 个家庭成员共同使用；
- 家长 A 创建家庭空间并设置课程，向其他成员发送**邀请链接或邀请码**；
- 其他成员需要登录并接受邀请，才能访问共享课程；
- 家人查看同一份数据。`member` 可打卡、请假、补课、撤销；`owner` 另外管理课程、排课、课包和成员。
- 记录由谁打卡、谁修改、修改时间。
- 提供基本登录和退出登录，不要求短信验证码或第三方付费认证（可先采用账号密码/用户名 + 密码）；
- 应有安全的密码哈希、认证 session/token、受保护的 API、家庭 ID 级数据访问隔离；不能仅依赖浏览器页面隐藏按钮来做权限控制。

V1 角色只有 `owner` / `member`。只读角色以后再做。

### 3.5 日历与首页

- **首页课程卡片**：名称、当前课包、已用/总数、剩余、进度条、下次排课、快速打卡。三个数字满足 **已用 + 剩余 = 总课时**（V1 没有赠送课时）。「已用」含启用前已用、已上课，以及明确扣课的请假。
- **日历月视图**：显示计划课程与实际记录；点击某天查看当天课程，可打卡、请假、补课、修改；
- 最近操作记录（至少能查看谁何时打卡）；
- 显示剩余课时提醒，例如剩余 `<=3` 节时以文字/轻提示突出；阈值可先固定为 3 或在设置中配置；
- 移动端触控区域足够大，中文文案简洁。

### 3.6 备份与数据安全

- SQLite 数据文件必须位于持久化卷或明确的宿主机目录，**容器更新不能擦除数据**；
- 至少提供一条明确的备份与恢复流程，建议每日自动备份并保留滚动历史；
- 备份文件包含家庭数据，需限制权限，不放在网站可公开访问目录；
- 能导出 CSV/JSON 作为额外保险（V1 可先完成后端导出，UI 不必复杂）；
- 所有数据库写操作需要事务；关键字段加唯一约束/索引以防重复打卡。

## 4. 用户流程（用于验收）

**首次使用：**

1. 家长创建账号与家庭空间“悠悠的家”。
2. 新增英语课，设置每周一 16:30、周五 19:00。
3. 添加第一期课包，填写实际购买课时数（由用户填写，不预填虚构数据）。
4. 新增舞蹈课及其课包，按实际信息设置时间。
5. 邀请另一位家人加入并登录。

**日常操作：**

1. 家人打开 H5，首页看到课程与剩余节数。
2. 某次课程结束后点击“已上课”。
3. 界面立即更新「已用 / 剩余」，显示当天记录及操作人。已用 + 剩余 = 总课时。
4. 另一位家人登录/刷新，同样看到更新结果。
5. 如果误打卡，可以撤销，剩余课时恢复；不会因两人几乎同时点击而消耗两次。

**特殊情况：**

- 请假：标记请假，默认不扣课时；若机构按规则扣课时，显式设置扣除。
- 补课：在原计划以外新增补课记录，实际上完后扣课时。
- 漏打卡：过几天回填实际日期，统计仍然正确。
- 续费：新建下一期课包，旧记录可查询。
- 课程安排变动：修改未来重复计划，不改写过去已发生的签到历史。

## 5. 建议数据库实体与约束

表名仅供参考，Cursor 可调整但不可丢失关键语义：

| 实体 | 主要字段 / 用途 |
|---|---|
| `users` | display_name, login_name（小写唯一）, password_hash |
| `sessions` | user_id, token_hash, expires_at；退出即失效 |
| `families` | name, owner_user_id |
| `family_members` | family_id, user_id, role；联合唯一 |
| `invitations` | family_id, code_hash, expires_at, used_by, used_at；一次性，默认 7 天 |
| `courses` | family_id, name, color, teacher, location, notes, active, current_package_id |
| `course_schedules` | course_id, weekday（周一=0）, local_time, effective_from, effective_to |
| `course_packages` | course_id, title, total_units, opening_consumed_units, start_date, expiry_date, notes |
| `lesson_records` | course_id, package_id, local_date, local_time, source, status, consumed_units, idempotency_key, voided_at, 操作者与时间 |
| `audit_logs` | actor, family_id, target, action, summary（含课时变化） |

不建未来课的 `lesson_occurrences`。字段级约束、幂等键和余额公式见 `docs/DECISIONS.md` 的 D6、D7。

建模时注意：

- 余额 = `total_units - opening_consumed_units - 未作废记录的 consumed_units 之和`。启用前已用写在课包上，修改它要记日志，不能悄悄改总课时来轧差。
- 计划课的幂等键是 `plan:{course_id}:{日期}:{时间}`。补课的键是 `manual:{uuid}`，所以同一天可以有多节。唯一约束不能只有 `(course_id, date)`。
- 作废记录仍保留。唯一索引只约束「未作废」的幂等键，撤销后才能再次打卡。
- 改排课是把旧时段的 `effective_to` 收到变更日前一天，并新增一条时段。已写的打卡带着自己的日期和时间，不跟着新课表走。
- 快捷打卡只用该课程的当前课包。不自动跨包结转。剩余为 0 时拒绝，V1 不透支。
- 时间戳存 UTC。用户选的日期和星期按 `Asia/Shanghai` 解释。到期日只展示，V1 不因为过期而禁止打卡。

### 已达成的系统选择

- **保留 AlmaLinux 9，不重装 Ubuntu**。系统自带的 Python 与 sqlite 足够跑这个应用。V1 不安装 Docker。
- 现有 VPN 正在服务，**不能中断或破坏**。重装会清空软件和配置、要求 VPN 恢复，因此不应为了小网站重装。
- 用户可在**公司 Ubuntu / Windows 开发**，之后通过 Git + SSH/CI 部署到日本 VPS。Windows 可用 WSL2；不要求开发机与服务器同发行版。
- 项目不依赖腾讯云，不需要额外购买云数据库。已有 VPS 成本视为既有支出；域名可能产生年费，HTTPS 证书可免费签发。

### 部署前必须只读检查

```bash
cat /etc/os-release
uname -m
free -h
df -h
ps aux --sort=-%mem | head -15
sudo ss -tulpn
command -v docker && docker --version
command -v docker && docker compose version
getenforce
```

执行这些检查是为了确认：真实内存余量、VPN 占用的监听端口、80/443 是否可用、SELinux 状态。其中 Docker 命令只为了解机器现状，**V1 不安装、不启动 Docker**。**不要未经核实直接占用 443、关闭 SELinux、防火墙或调整 VPN。**

### 推荐部署设计

- 生产环境运行：Caddy 托管静态 H5，反代到单个 uvicorn 进程，SQLite 打开 WAL。
- 不在这台 1 GB VPS 上安装 Docker。本地也不把 Docker 当作开发前提。
- 采用独立目录存储数据库、备份、日志；使用 `.env` 管理密钥，`.env` 禁止提交 Git。
- HTTPS 公网访问；SSH 认证、系统防火墙、暴露端口需审查。
- 日本 VPS 不必因**普通 H5 网站**而直接迁移中国大陆服务器，但**国内访问可能受跨境网络质量影响**。请用**未开启 VPN 的中国大陆手机网络**测试域名解析、HTTPS 与页面可用性。
- **如果 VPS 只通过私网 VPN 访问、没有可用公网 Web 入口**，需要先评估公网 IP、端口及 HTTPS 方案，不能直接保证家人无需 VPN。
- 未来小程序的 API 域名/备案/合法域名要求，届时重新核实；H5 能访问 ≠ 小程序审核一定通过。

## 7. MVP 页面草案

1. **登录 / 加入家庭**：账号密码登录、创建家庭或使用邀请码加入。
2. **课程首页**：总剩余课时、本月上课次数、每门课程卡片、最近打卡、快捷打卡。
3. **日历页**：月视图按课程颜色标点；选择日期查看当日课程与状态；支持补录与纠错。
4. **课程详情页**：课包进度、上课安排、历史签到记录、续报新课包。
5. **设置页**：编辑课程和排课、家庭成员管理、邀请码、数据导出。

UI 风格：简洁、清爽、对家长友好；不要复杂动画。默认优先适配 375px 左右手机视口以及微信内置浏览器；桌面可查看但不是首要场景。常用操作不超过 2–3 次点击。

## 13. 本次讨论最终决策摘要

- **现在先开发 H5**，将来可迁移微信小程序，不开发原生 App。
- **Cursor Agent 主导开发**；ChatGPT 可帮助需求评审和技术复核。

- VPS 配置 **1GB RAM / 20GB 系统盘 / 1TB 月流量**，足以先尝试部署这类轻量家庭应用；优先使用 SQLite 和低内存后端。
- **无需以腾讯云为前置条件**，家庭访问依赖日本 VPS 的公网 HTTPS 可达性；是否需要 VPN 取决于网络和入口配置，必须实测。
- **小程序备案、域名和上线审核留到未来阶段评估**，不要因为它们阻塞当前 H5 MVP。
- **2026-10-08 复审：** 前端锁定 Vue 3 + Vite；计划课现算、打卡才落库；当前课包单点扣课；成员不能改课程结构；生产用 systemd + Caddy，不用 Docker。
